### **Step 0.2: Schema & NULL Analysis (2 hours)**

**Task**: Hiểu tại sao các fields có NULL pattern khác nhau theo event type.

**Discovery Task**: Why do some fields have NULL for certain event types?

```python
# Check NULL patterns by event type — chạy trên sample
for event in df['collection'].unique():
    subset = df[df['collection'] == event]
    print(f"\n{event} ({len(subset)} rows):")
    print(f"  product_id NULL: {subset['product_id'].isna().sum() / len(subset) * 100:.1f}%")
    print(f"  order_id NULL:   {subset['order_id'].isna().sum() / len(subset) * 100:.1f}%")
    print(f"  user_ip NULL:    {subset['user_ip'].isna().sum() / len(subset) * 100:.1f}%")
```

**Questions to Answer**:

- Những field nào luôn có giá trị (không bao giờ NULL)?
- Tại sao `checkout_success` có `order_id` nhưng `view_product_detail` thì không?
- Đây có phải vấn đề data quality hay là thiết kế có chủ đích?

**Key Discovery**:

- Different event types track different attributes — đây là **"schema-on-read"** pattern
- MongoDB lưu flexible schema: mỗi document có thể có fields khác nhau
- `checkout_success` → có `order_id`, `cart_products` (nested array)
- `view_product_detail` → có `product_id`, không có `order_id`

**Document findings vào notebook** (thêm markdown cells giải thích).

> ✅ **Checkpoint #1 passed khi**: Đã giải thích được tại sao NULL pattern khác nhau, không chỉ đo số liệu.
>

> 💡 **Survival Tips khi bị Block IP**: Đây là kịch bản THỰC TẾ.
> 
> - Dùng `random.uniform(1.5, 4.2)` thay vì `sleep(1)` tĩnh
> - Search thư viện `fake_useragent` để rotate User-Agent header sau mỗi request
> - Dùng `try...except` để script không crash khi gặp 1 URL lỗi, log lại URL đó để retry sau
> - Chia nhỏ batch, nghỉ giữa các batch (ví dụ: crawl 500 → sleep 3s)
