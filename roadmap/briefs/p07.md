- Build supporting dimension tables to enrich the fact data by capturing all contextual dimensions (Who, What, Where, When, and How).
    
    <aside>
    💡
    
    You should follow some conventions while design your model.
    
    ## 🔹 **Table Naming**
    
    - **Dimension tables**: `dim_<entity>`
        - Examples:
            - `dim_customer`
            - `dim_product`
            - `dim_date`
    - **Fact tables**: `fact_<event>_<fact_table_type>`
        - Examples:
            - `fact_sales`
            - `fact_inventory`
            - `fact_order`
    
    ---
    
    ## 🔹 **Column Naming**
    
    - **Primary keys in dimensions**: `<entity>_key`
        - Example: `customer_key`, `product_key`, `date_key`
        - Use Integer or bigint
    - **Foreign keys in fact tables**: same name as the dimension key
        - Example: `customer_key`, `product_key`, `date_key`
    - **Natural keys (business identifiers)**:
        - Format: `<entity>_id` or `<entity>_code`
        - Example: `customer_id`, `product_code`
    - **Descriptive** **attributes:** Use `_name` for human-readable text:
        - `country_name` (e.g., “Viet Nam”)
        - `city_name` (e.g., “Ho Chi Minh City”)
        - `region_name` (e.g., “Southeast Asia”)
    - **Measures in fact tables**: use clear business terms
        - Example: `sales_amount`, `order_qty`, `discount_pct`
    - **Date/Time**:
        - Use `_date` for dates, `_time` for times, ..
    - **Booleans**:
        - Use `is_` or `has_`.
        - Example: `is_active`, `has_return`.
    - Description Columns
        - Use `_description` **only for longer, free-text, explanatory fields**.
        - Example:
            - `product_description` → "Lightweight running shoes with breathable mesh."
            - `promotion_description` → "10% off all electronics during Black Friday."
    
    ---
    
    ## 🔹 **Schema Naming**
    
    - Group by data layer or domain:
        - `staging`, `core`, `mart`
        - Or business domains: `sales`, `inventory`, `finance`.
    
    ---
    
    ## 🔹 **Data Type Conventions**
    
    - Dimension keys → `INT` or `BIGINT`
    - Business codes/natural keys → `VARCHAR`
    - Numeric facts → `DECIMAL(18,2)` for money, `INT` for counts
    - Dates → `DATE`
    - Timestamps → `TIMESTAMP` (with timezone if possible)
    
    ---
    
    ## 🔹 **SQL Formatting**
    
    - Keep your earlier rules:
        - Uppercase SQL keywords (`SELECT`, `WHERE`)
        - Lowercase for schema/table/column names
        - Comma **before** column, aligned formatting
        - Always include schema (`mart.fact_sales`)
    
    ```sql
    SELECT item_id, item_name, brand_id 
    FROM sales.product
    ```
    
    - Put the comma before item, add space before and after  ‘=’,  comparison operator
    
    ```sql
    SELECT 
    	item_id
    	,item_name
    	,brand_id 
    FROM sales.product
    WHERE item_name = 'sua'
    	AND quantity > 100
    ```

### Implement data transformation (20 hours)

- Apply data transformations to every table in your data model.
    
    ```sql
    
    -- Example dimension model
    WITH source_data AS (
        SELECT DISTINCT
            product_id,
            product_name,
            category,
            price
        FROM glamira_raw.product_raw
        WHERE product_id is not null
    )
    SELECT *
    FROM source_data
    
    ```
